## Descripción del ticket

**Como** usuario de Dough
**Quiero** recibir una sugerencia de presupuesto mensual por categoría de la TRX al activar Smart Budget
**Para** tener un punto de partida realista basado en mi propio comportamiento financiero, sin tener que construirlo desde cero

---

## Contexto

Smart Budget Fase 0 — El Reflejo. El modelo toma el historial transaccional del usuario y proyecta un monto sugerido por categoría. No hay intención declarada ni ajuste contextual en esta fase — es pura estadística sobre comportamiento pasado.

**Prerequisito:** DATA-1066 — define la lógica base del modelo, prepara el dataset y establece el output schema. Esta US asume que esa definición está completa antes de arrancar.

**Fuente de datos:** Acceso directo a DB (warehouse). Analytics no requiere intermediación de Dough.

---

## Enfoque técnico (definido en DATA-1066)

**Modelo baseline:** Approach basado en mediana por subcategoría.

**Nivel de agregación del dataset:** usuario / categoría / mes.

Si DS considera que un promedio ponderado u otro método mejora el resultado frente a la mediana, puede adoptarlo — el requisito de producto es que `suggested_amount` sea representativo del comportamiento habitual del usuario en esa categoría.

---

## Requerimientos de producto

- **Scope de categorías:** Todas las categorías del usuario con data transaccional suficiente.
- **Solo transacciones Posted** — las Pending no entran en el cálculo.
- **Ventana por defecto:** **3 meses**. Configurable por CU en un rango de **3 a 24 meses**.
- **Gating:** Si una categoría tiene **menos de 3 meses** de historia, no se genera sugerencia — se omite del output. El UI mostrará el campo vacío con mensaje explicativo.
- **Outliers:** Los meses con gastos atípicamente altos o bajos **deben suavizarse, no excluirse**, para que no dominen la sugerencia. El mecanismo de suavizado es decisión de DS.

## Output esperado (por subcategoría con suficiente data)

```json
{
  "category_id": "string",
  "subcategory_id": "string",
  "suggested_amount": "number",
  "basis": {
    "months_analyzed": "number",
    "data_points": "number",
    "period_range": "YYYY-MM ~ YYYY-MM"
  },
  "display_label": "string"
}
```

`display_label` ejemplo: `"Based on your last 3 months"`

## Criterios de aceptación

- [ ] El modelo genera un `suggested_amount` por categoría para usuarios con 3+ meses de historia
- [ ] El dataset está agregado a nivel usuario / categoría / mes
- [ ] Los meses con gastos extraordinarios no distorsionan la sugerencia de forma desproporcionada
- [ ] Categorías sin suficiente historia se omiten del output
- [ ] El output incluye `months_analyzed` y `period_range` para transparencia en el UI
- [ ] DS documenta el approach elegido y el razonamiento (incluyendo justificación si se desvía de la mediana base)
